# MicroHySeeker AI 实验管家 — 需求分层分析与定位

> 生成日期：2026-02-14
> 目的：在动手实现前，先理清需求层级、明确定位、确定功能范围，再选择实施路径。

---

## 一、定位：AI 实验管家（Experiment Steward）

### 1.1 一句话定位

> **为微流体电化学高通量筛选平台提供智能辅助，覆盖"实验前规划 → 实验中监控 → 实验后分析"全流程，降低科研人员重复劳动，提升实验效率与数据洞察质量。**

### 1.2 三层角色模型

| 角色层级 | 类比 | 说明 |
|----------|------|------|
| **L1 — 数据助手** | 实验室的"数据员" | 帮你整理、查看、导出数据，自动生成图表和报告 |
| **L2 — 分析顾问** | 实验室的"分析师" | 帮你分析电化学数据、诊断问题、发现规律、给出建议 |
| **L3 — 实验管家** | 实验室的"主管" | 帮你规划实验、优化参数、自主调度实验流程、闭环迭代 |

> **建议**：从 L1 做起，逐步演进到 L2，L3 是长期愿景。每一层都是下一层的基础。

## 四、L2 — 分析顾问（智能层）

> **核心价值**：把专业分析能力"内化"到系统中，即使新手也能获得专家级的数据洞察
> **是否需要 LLM**：部分需要（自然语言交互、复杂推理），部分用传统算法即可
> **预估工作量**：3-6 周

### L2.1 电化学数据自动分析（传统算法）

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|
| CV 氧化/还原峰自动识别 | ⭐⭐ | scipy.signal | find_peaks 检测峰位置、峰电流 |
| ΔEp、峰电流比计算 | ⭐ | numpy | 可逆性判断指标 |
| 基线校正 | ⭐⭐ | scipy | 去除基线漂移 |
| 数据质量评分 | ⭐⭐ | 规则引擎 | 噪声、异常点、信号强度评估 |
| 扩散系数估算 | ⭐⭐⭐ | 电化学理论 | Randles-Sevcik 方程拟合 |
| EIS 等效电路拟合 | ⭐⭐⭐⭐ | impedance.py | Nyquist/Bode 图 + 电路模型 |

### L2.2 多实验对比与趋势分析（传统算法 + 可选LLM总结）

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|
| 同参数多次重复性分析 | ⭐⭐ | scipy.stats | RSD、CV 等统计指标 |
| 不同浓度/条件对比 | ⭐⭐ | pandas | 峰电流 vs 浓度线性关系 |
| 跨天趋势追踪 | ⭐⭐⭐ | pandas + matplotlib | 关键指标随时间变化 |
| 异常实验自动标记 | ⭐⭐ | 统计方法 | 偏离正常范围的实验 |
| **LLM 自然语言总结** | ⭐⭐ | OpenAI/Ollama | "总结这组实验的关键发现" |

### L2.3 实验前校验与辅助（规则 + 可选LLM）

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|
| 浓度计算验证 | ⭐ | 数学计算 | 检查配液参数是否数学正确 |
| 参数合理性检查 | ⭐⭐ | 规则库 | 扫速范围、电位窗口是否合理 |
| 历史参数推荐 | ⭐⭐ | 统计分析 | 基于历史数据推荐最优参数 |
| **LLM 实验方案审查** | ⭐⭐⭐ | OpenAI/Ollama | AI 审查实验方案并给建议 |

### L2.4 故障诊断（规则 + LLM）

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|
| 错误日志自动分类 | ⭐⭐ | 正则/规则 | 将错误归类为硬件/软件/参数/通讯 |
| 常见故障自动诊断 | ⭐⭐ | 决策树 | 如 RS485 超时 → 检查线缆/地址 |
| 泵操作异常检测 | ⭐⭐ | 统计 | 流速偏差、堵塞检测 |
| **LLM 智能诊断** | ⭐⭐⭐ | OpenAI/Ollama | "为什么这个实验失败了？" |
| 校准漂移监测 | ⭐⭐ | 线性回归 | 泵精度随时间退化预警 |

### L2.5 AI 对话界面（核心集成）

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|
| 聊天面板 UI | ⭐⭐ | PySide6 | 右侧/浮动窗口，Markdown 渲染 |
| LLM API 接入 | ⭐⭐ | OpenAI SDK | 支持 OpenAI / 本地 Ollama |
| Function Calling/Tool Use | ⭐⭐⭐ | LLM 框架 | 让 LLM 调用内部分析函数 |
| 上下文管理 | ⭐⭐ | 自定义 | 实验数据摘要、历史对话 |
| 流式输出 | ⭐⭐ | SSE/Streaming | 打字机效果输出 |

## 五、L3 — 实验管家（自主层）

> **核心价值**：AI 从"被动回答"升级为"主动行动"，真正的实验自动化智能体
> **是否需要 LLM**：核心依赖 LLM + Agent 框架
> **预估工作量**：2-6 个月
> **前置条件**：L1 + L2 基本完成

### L3.1 实验方案智能生成

| 功能 | 难度 | 依赖 | 说明 |
|------|------|------|------|

### L3.2 自主实验调度（Multi-Agent）

## 十、总结与建议

### 核心观点

1. **不要一步到位做 Multi-Agent**。先把**数据分析工具包（L1+L2.1）** 做扎实，这是所有 AI 功能的地基。
2. **传统算法优先于 LLM**。CV 峰值检测、统计对比、错误分类等用 scipy/pandas 就能做好，不需要 LLM。
3. **LLM 的价值在于"胶水"和"交互"**。让用户用自然语言触发分析、让 AI 整合多个分析结果给出总结。
4. **Multi-Agent 是 L3 的事**。在工具层没建好之前，Agent 无"手"可用，架构再好也空转。

### 推荐的最小启动包

```
第 1 步：EChemAnalyzer（电化学分析工具类）
       ├── detect_cv_peaks()
       ├── calculate_reversibility()
       ├── assess_data_quality()
       └── compare_experiments()

第 2 步：ReportGenerator（报告生成器）
       ├── single_run_report()
       └── daily_summary()

第 3 步：DiagnosticEngine（诊断引擎）
       ├── classify_error()
       └── suggest_fix()

第 4 步：AI Chat Panel（可选，如果有 LLM API）
       ├── ChatWidget (PySide6 UI)
       ├── LLMService (API 封装)
       └── ToolRegistry (注册上面的工具)
```
