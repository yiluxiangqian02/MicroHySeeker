## ① 文献与知识获取域

> **核心问题**：科研中大量时间花在"找文献、读文献、整理文献"上，LLM 可以大幅加速这个过程。

### 1.1 文献智能检索

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **语义搜索文献** | 不是关键词匹配，而是语义理解："找到用微流体做 Fe 浓度梯度电化学检测的论文" | RAG + 向量检索 |
| **跨数据库聚合** | 同时搜索 PubMed, Web of Science, Google Scholar, arXiv, 知网, 万方 | Agent + API |
| **相关性排序与过滤** | AI 判断与你当前实验课题的相关性，自动过滤低相关论文 | LLM 打分 |
| **引文网络分析** | 给定一篇核心论文，自动追踪其引用和被引，发现关键节点论文 | Graph + LLM |
| **领域新文献推送** | 定期监控领域新论文，自动摘要推送"本周有什么新进展" | 定时任务 + LLM |

### 1.2 文献深度阅读

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **论文自动摘要** | 上传 PDF，生成结构化摘要（目的、方法、结果、结论、创新点） | LLM 长文本理解 |
| **方法段提取** | 从论文中精确提取实验参数（扫速、电位范围、浓度、电极材料等） | LLM + 结构化输出 |
| **对比表生成** | 给 N 篇论文，自动生成方法/结果对比表 | LLM + 表格生成 |
| **批判性评价** | AI 点评论文的优缺点、实验设计是否严谨、数据是否支持结论 | LLM 推理 |
| **翻译与术语解释** | 跨语言论文翻译 + 专业术语上下文解释 | LLM 翻译 |

### 1.3 领域知识问答

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **电化学理论咨询** | "Randles-Sevcik 方程中，扩散系数怎么估算？" | LLM 知识 |
| **材料属性查询** | "IrO₂ 在酸性 OER 中的 Tafel 斜率通常是多少？" | LLM + RAG |
| **实验方法论指导** | "EIS 测量时频率范围怎么选？为什么？" | LLM 知识 |
| **仪器原理解释** | "CHI 660F 的 DPV 模式中各参数含义是什么？" | RAG（仪器手册） |
| **领域综述生成** | "帮我梳理微流体电化学传感器的发展脉络（2020-2025）" | LLM + 文献 RAG |

## ② 假说与实验设计域

> **核心问题**：实验设计往往依赖经验，LLM 可以基于文献 + 历史数据辅助设计更好的实验。

### 2.1 科学假说辅助

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **假说生成** | 基于已有数据和文献，AI 提出可测试的假说："根据你的 CV 数据，该催化剂可能存在双电子转移机制" | LLM 推理 |
| **假说验证实验建议** | 给定假说，建议需要做哪些实验来验证/推翻 | LLM 推理 |
| **竞争假说分析** | 列出数据可能支持的多种解释，分析各自的证据强度 | LLM 分析 |

### 2.2 实验方案生成

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **自然语言 → 实验方案** | "我想测试 5 种 Fe/Co 比例在 0.1-0.5M 浓度区间的 OER 性能" → 生成完整的 MicroHySeeker 实验 JSON | LLM + Schema |
| **方案模板推荐** | 根据实验目的推荐预设模板（催化剂筛选模板、浓度标定模板、电极评估模板） | LLM 匹配 |
| **对标文献方法复现** | 从论文方法段自动生成与本平台兼容的实验方案 | LLM + 方法提取 |
| **方案合理性审查** | AI 审查实验方案："扫速 10V/s 可能导致 iR 降过大，建议降低或使用 iR 补偿" | LLM + 领域知识 |

### 2.3 参数空间设计

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **DOE (实验设计法)** | 自动生成正交设计、拉丁超立方、全因子设计的参数矩阵 | 优化算法 + LLM 解读 |
| **贝叶斯优化** | 根据已有实验结果，智能选择下一组参数（最大化信息增益或目标函数） | BoTorch/Optuna + LLM 解释 |
| **约束感知推荐** | 考虑硬件限制（泵流速范围、电位窗口、通道数）推荐可行参数组合 | 规则 + LLM |
| **敏感性分析** | 分析哪些参数对结果影响最大，推荐重点调优方向 | 统计分析 + LLM 解读 |

### 2.4 安全与合规审查

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **实验安全检查** | 检查溶液组合是否有安全风险（如强酸 + 强氧化剂） | LLM 安全知识库 |
| **参数越界警告** | 检测电位范围是否可能损毁电极或引发副反应 | 规则 + LLM |
| **操作风险评估** | 高通量长时间无人实验时的风险分析和应急方案建议 | LLM |

## ③ 实验执行与监控域

> **核心问题**：实验运行时需要人盯着，出错了不知道怎么办，LLM 可以做智能监控和自主决策。

### 3.1 智能实验调度

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **实验队列智能编排** | 根据优先级、预计耗时、试剂消耗自动编排当天实验队列 | Agent 调度 |
| **资源冲突检测** | 检测多个实验是否争用同一泵/通道，自动排解冲突 | 规则引擎 |
| **实验依赖链管理** | 实验 B 需要实验 A 的结果才能确定参数 → 自动串联 | Agent workflow |
| **批次分组优化** | 将大量组合实验分成高效批次，减少冲洗和切换次数 | 优化算法 |

### 3.2 实时监控与异常干预

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **数据质量实时监控** | 电化学数据采集时实时判断：噪声是否过大、是否有气泡、信号是否异常 | 在线检测算法 + LLM |
| **实时异常报警** | 检测到异常立即通知（弹窗/微信/邮件），附带初步诊断 | Agent + 通知 |
| **自动重试策略** | 数据质量不合格 → 自动重做当前步骤（可配置重试次数和条件） | Agent 决策 |
| **在线调参建议** | 实验进行中，基于已有结果建议后续参数调整 | LLM 推理 |

### 3.3 自主实验闭环（高级）

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **实验-分析-决策循环** | 做完一轮 → AI 分析结果 → AI 决定下一轮参数 → 继续实验（无人值守） | Multi-Agent |
| **目标驱动搜索** | 给定目标（如"找到 OER 过电位最低的催化剂组成"），AI 自主规划并执行搜索 | Agent + 优化 |
| **早停决策** | AI 判断当前方向已无继续价值时，主动建议终止并切换方向 | LLM 推理 |
| **跨实验学习** | 前一组实验学到的规律，自动应用到后一组实验的参数选择 | 在线学习 |

## ④ 数据处理与分析域

> **核心问题**：数据分析是最高频的需求，但不应只停留在"调库函数"层面，LLM 的价值在于**理解和解释**。

### 4.1 自动化数据处理

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **电化学特征自动提取** | CV 峰值、Tafel 斜率、EIS 拟合参数、i-t 稳态电流等 → 自动提取到结构化表 | 算法（非 LLM） |
| **数据清洗与预处理** | 自动去噪、基线校正、异常点剔除、数据对齐 | 算法 |
| **批量自动处理** | "把今天 30 组实验全部做 CV 分析" → 批量运行所有分析并汇总 | Agent 编排 |

### 4.2 智能数据解读（LLM 核心价值）

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **自然语言解读数据** | "这个 CV 说明了什么？" → AI 给出电化学专业解读 | LLM + 领域知识 |
| **多维数据关联分析** | 关联分析：浓度 vs 峰电流 vs 扫速 vs 电极面积 → 发现缺失的物理关系 | LLM + 统计 |
| **异常值溯源** | "第 7 组实验数据异常" → AI 回溯该组的配液/冲洗记录找原因 | Agent 链式推理 |
| **结果置信度评估** | AI 评估当前数据量是否足以支持结论，是否需要更多重复实验 | LLM 统计推理 |
| **cross-experiment insight** | 跨越不同日期/不同项目发现数据中的隐含规律 | LLM + 数据挖掘 |

### 4.3 可视化与图表

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **自然语言生成图表** | "画一个峰电流 vs 浓度的标定曲线" → 自动绘图 | LLM → matplotlib code |
| **图表美化与规范化** | 按论文投稿要求自动调整图表格式（字体、DPI、Color scheme） | LLM + 模板 |
| **交互式探索** | AI 引导的数据探索："你想从哪个角度看这组数据？" | Agent 交互 |

## ⑤ 故障诊断与运维域

> **核心问题**：实验出错是常态，诊断费时费力，LLM 可以做"老师傅级别"的故障分析。

### 5.1 错误智能诊断

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **日志自动分析** | 解析 run_log.log，定位错误发生的上下文和根因 | LLM 文本理解 |
| **错误知识库匹配** | 将当前错误与历史同类错误匹配，找到曾经有效的解决方案 | RAG |
| **多因素根因分析** | "实验失败了" → AI 检查硬件状态、配液记录、通讯日志、环境因素 → 综合判断 | Agent 多源推理 |
| **对话式排错** | AI 像技术支持一样逐步引导排查："请检查串口线连接 → 查看泵地址设置 → ..." | LLM 对话 |

### 5.2 预测性维护

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **泵校准漂移检测** | 追踪泵精度随时间变化，预测何时需要重新校准 | 时序分析 |
| **耗材寿命预估** | 根据使用频率和历史数据预估管路、电极、密封件寿命 | 统计模型 |
| **硬件健康评分** | 综合各硬件指标给出系统健康度评分和维护建议 | LLM 综合评估 |
| **异常模式识别** | 检测泵操作中的异常模式（堵塞前兆、打滑、通信不稳定） | 模式识别 |

### 5.3 自动恢复

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **常见故障自动修复** | RS485 超时 → 自动重试 → 重新建立连接 → 继续实验 | Agent + 规则 |
| **降级运行策略** | 某个泵不可用 → AI 自动调整方案绕过该泵继续 | Agent 决策 |
| **恢复后验证** | 自动恢复后执行验证动作确认系统状态正常 | Agent workflow |

## ⑥ 科研写作与报告域

> **核心问题**：从数据到论文之间有巨大的"最后一公里"，LLM 可以大幅加速写作过程。

### 6.1 实验报告自动生成

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **单次实验报告** | 自动生成包含方案、参数、数据、图表、初步结论的完整报告 | LLM + 模板 |
| **每日/每周汇总** | 汇总一段时间内所有实验的关键指标和进展 | LLM 摘要 |
| **对比实验报告** | 选择一组实验，自动生成对比分析报告 | LLM + 分析工具 |
| **多格式导出** | Markdown / Word / PDF / LaTeX / HTML | 模板引擎 |

### 6.2 论文写作辅助

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **Methods 段落生成** | 根据实验方案 JSON + 运行参数，自动生成符合期刊格式的方法描述 | LLM 写作 |
| **Results 段落辅助** | 基于数据分析结果，生成结果描述和数据讨论的草稿 | LLM 写作 |
| **Discussion 辅助** | 将实验结果与文献进行对比讨论，生成 discussion 草稿 | LLM + RAG |
| **Abstract / Conclusion** | 基于全文内容生成摘要和结论 | LLM 摘要 |
| **SI (补充材料) 生成** | 自动整理补充图表、原始数据表、详细方法 | LLM + 工具 |
| **语言润色** | 中文草稿 → 学术英文；或英文语法/表达优化 | LLM 翻译/润色 |

### 6.3 图表与可视化

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **论文级图表生成** | 符合特定期刊要求的高质量图表（双轴/嵌入图/分面图） | LLM → 代码 |
| **TOC 图辅助** | 生成论文 Table of Contents 图的设计建议 | LLM 创意 |
| **图表说明生成** | 为图表自动生成 Figure Caption | LLM 写作 |

### 6.4 演示与汇报

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **PPT 大纲生成** | 根据实验数据和结论，生成组会/汇报 PPT 的大纲和要点 | LLM 生成 |
| **口头汇报脚本** | 为每页 PPT 生成演讲稿 | LLM 生成 |
| **Q&A 预演** | AI 模拟审稿人/导师提问，帮你准备答辩 | LLM 角色扮演 |

## ⑦ 知识管理与积累域

> **核心问题**：实验室的经验和知识大量存在于"人脑"和"散落的笔记"中，人走了知识就丢了。

### 7.1 实验知识库

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **实验语义检索** | "之前做过的 Fe 催化剂 CV 扫描有哪些？效果最好的是哪个？" | RAG + 向量 DB |
| **参数-结果知识图谱** | 自动构建"参数组合 → 实验结果"的关联网络 | 知识图谱 |
| **最佳实践沉淀** | 从历史实验中提取"什么条件下效果最好"形成知识条目 | LLM 归纳 |
| **失败经验记录** | 自动记录并索引"踩过的坑"——哪些参数组合不可行，为什么 | LLM + DB |

### 7.2 跨项目知识迁移

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **跨课题经验借鉴** | 课题 A 的配液优化经验，是否适用于课题 B？ | LLM 迁移推理 |
| **方法论复用** | 识别不同项目中通用的实验方法论和参数模式 | LLM 模式发现 |
| **历史数据二次利用** | 对旧数据用新方法重新分析，发现当时遗漏的发现 | Agent + 分析 |

### 7.3 领域知识体系

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **电化学概念映射** | 构建电化学子领域的概念关系图（技术→原理→参数→应用） | LLM + 本体 |
| **术语标准化** | 统一实验室内的术语使用（"扫速" vs "扫描速度" vs "scan rate"） | LLM 归一化 |
| **方法选择决策树** | "我要测 XXX，应该用什么电化学技术？" → 交互式引导 | LLM 知识 |

## ⑧ 协作与教学域

> **核心问题**：实验室多人协作、新人上手都需要成本，AI 可以当"虚拟师兄/师姐"。

### 8.1 培训与上手

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|

## ⑨ 研究策略与元认知域

> **核心问题**：不只做实验，还要做"对的实验"。AI 帮你站在更高维度思考研究方向。

### 9.1 研究方向辅助

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **领域热点分析** | 分析近 N 年发文趋势、高被引方向、新兴主题 | LLM + 文献数据 |
| **差距分析 (Gap Analysis)** | "我们当前的研究在该领域处于什么位置？还有哪些空白？" | LLM 分析 |
| **竞争对手追踪** | 监控特定课题组/作者的最新发表和研究方向 | Agent 监控 |
| **选题可行性评估** | 评估一个研究方向的创新性、可行性、预期影响力 | LLM 综合评估 |

### 9.2 研究规划

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **实验优先级排序** | 有限时间内应该先做哪些实验？ROI 最高的方向是？ | LLM 决策辅助 |
| **里程碑规划** | 帮你拆解研究目标为可执行的里程碑和时间表 | LLM 规划 |
| **基金申请辅助** | 生成研究计划、技术路线图、创新点描述的草稿 | LLM 写作 |
| **科研复盘** | 定期回顾：做了什么、发现了什么、下一步怎么调整 | LLM 引导反思 |

### 9.3 科研伦理与规范

| 子需求 | 描述 | LLM 角色 |
|--------|------|----------|
| **数据完整性检查** | 检测数据是否有异常的"整齐"（可能的图片复制/数据伪造预警） | 统计检测 |
| **实验可重复性评估** | 分析实验的重复性，生成可重复性报告 | 统计 + LLM |
| **引用规范检查** | 检查论文草稿中的引用是否准确、格式是否规范 | LLM + 文献 DB |
