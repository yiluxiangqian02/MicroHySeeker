# 运行日志故障反馈实现说明

## 结论

已对照 [运行日志故障反馈.md](f:/micro/MicroHySeeker/MicroHySeeker/docs/%E8%BF%90%E8%A1%8C%E6%97%A5%E5%BF%97%E6%95%85%E9%9A%9C%E5%8F%8D%E9%A6%88.md) 逐条核查。当前文档中列出的功能已覆盖，不仅仅是“RS485 / 泵状态变化”这一项。

## 已实现功能

### 1. 主界面运行日志分级显示

已实现：

1. 主界面“运行日志”支持按 `DEBUG / INFO / WARNING / ERROR / CRITICAL` 分级显示。
2. 日志显示格式已统一为：

```text
[HH:MM:SS] [LEVEL] [SOURCE] message
```

3. 日志颜色已按级别区分：
   - `INFO`：黑色
   - `DEBUG`：灰色
   - `WARNING`：橙色
   - `ERROR / CRITICAL`：红色

### 2. 实验执行故障反馈

以下故障已进入主界面“运行日志”：

1. 预检查失败
   - 日志文案示例：`[预检查失败] ...`
   - 日志文案示例：`[实验] 预检查发现 N 个错误，实验无法启动`
2. RS485 未连接
   - 日志文案示例：`RS485 端口未连接，无法操作泵 ...`
3. 泵启动失败
   - 日志文案示例：`泵X 启动命令发送失败`
   - 日志文案示例：`泵X 启动失败 — 重试后编码器仍无变化`
4. 泵位置命令发送失败
   - 日志文案示例：`泵X 位置命令发送失败`
5. 泵编码器无变化
   - 日志文案示例：`控制器报运行但编码器无变化`
   - 日志文案示例：`重试后编码器仍无变化，无法启动`
6. 泵持续减速超时
   - 日志文案示例：`持续减速 10s，强制停止`
7. 泵堵转保护触发
   - 日志文案示例：`堵转保护触发`
8. 泵堵转清除失败
   - 已以故障恢复失败的最终结果形式进入日志
   - 日志文案示例：`堵转无法恢复`
9. 步骤执行异常 / 步骤执行失败
   - 日志文案示例：`[错误] ...`
   - 日志文案示例：`[步骤i] 执行失败`
10. 电化学测量失败
   - 日志文案示例：`电化学测量失败: ...`
   - 日志文案示例：`电化学异常: ...`
11. 实验中断 / 执行失败
   - 日志文案示例：`[实验] 实验已停止`
   - 日志文案示例：`[实验] 执行失败`

### 3. 底层 RS485 / PumpManager 状态故障反馈

已实现：

1. 泵故障码出现
   - 文案：`泵 X 检测到故障: 堵转保护触发`
2. 泵故障清除恢复
   - 文案：`泵 X 故障已清除，状态恢复正常`
3. 泵通信超时 / 离线
   - 文案：`泵 X 通信超时或离线，请检查电源、地址和串口连线`
4. 泵通信恢复
   - 文案：`泵 X 通信已恢复`

说明：

1. 这一部分由 `PumpFaultTracker` 基于状态变化做去重触发，避免相同故障在界面中连续刷屏。
2. 只有“状态发生变化”时才会向运行日志追加一次事件。

### 4. 运行结果归档

已实现：

1. 实验运行期间所有 `WARNING` / `ERROR` 级别日志会持续写入实验目录的 `run_log.log`。
2. 同时会自动汇总到 `run_summary.json` 的：
   - `warnings`
   - `errors`
3. 汇总时做了去重，同一条消息只保留一份。

### 5. 验证情况

已完成以下验证：

1. 对照需求文档逐条检查代码路径。
2. 补充了自动化测试，覆盖：
   - 泵故障出现 / 恢复
   - 泵离线 / 恢复
   - `run_summary.json` 中 `warnings/errors` 去重汇总
3. 以 `offscreen` 模式实例化主窗口，手动注入：
    - 结构化 `ERROR` 日志
    - 泵故障状态变化
    并确认故障信息确实进入“运行日志”控件。
4. `_save_last_experiment` 失败、CHI/数据保存异常、实验中断等都会经 `log_message` 写入运行日志；目前打印提示的旧代码已改为 `warning` 级别日志串联到 `run_log.log` 和 `run_summary.json`，保证“实验/CHI/数据保存异常记录到运行日志”要求覆盖。
