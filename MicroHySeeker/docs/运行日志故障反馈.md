# 运行日志故障反馈

## 目标

当实验运行过程中出现故障、异常、通信掉线、泵堵转、步骤失败、电化学执行失败时，信息必须同时满足以下要求：

1. 立即显示在主界面的“运行日志”模块。
2. 在实验数据目录的 `run_log.log` 中持久化。
3. 在 `run_summary.json` 中汇总到 `errors` / `warnings`，便于后续追溯。

## 本次实现范围

### 1. 主界面运行日志分级显示

- `INFO`：普通运行信息，黑色显示。
- `DEBUG`：调试信息，灰色显示。
- `WARNING`：风险、超时、减速过久、重试等，橙色显示。
- `ERROR` / `CRITICAL`：故障、异常、失败，红色显示。

日志显示格式统一为：

```text
[HH:MM:SS] [LEVEL] [SOURCE] message
```

### 2. 实验执行故障反馈

以下故障必须进入主界面运行日志：

- 预检查失败
- RS485 未连接
- 泵启动失败
- 泵位置命令发送失败
- 泵编码器无变化
- 泵持续减速超时
- 泵堵转保护触发
- 泵堵转清除失败
- 步骤执行异常
- 电化学测量失败
- 实验中断 / 执行失败

### 3. 底层泵状态故障反馈

当底层 RS485 / PumpManager 状态变化时，主界面运行日志必须追加：

- 泵故障码出现
- 泵故障清除恢复
- 泵通信超时 / 离线
- 泵通信恢复

### 4. 运行结果归档

所有 `WARNING` / `ERROR` 级别日志需要自动汇总到：

- `run_summary.json -> warnings`
- `run_summary.json -> errors`

同一条消息只保留一份，避免重复堆积。
