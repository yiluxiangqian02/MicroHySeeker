   ```python
       """轮询数据（后台线程）"""
       e_buffer = (ctypes.c_double * 10000)()
       i_buffer = (ctypes.c_double * 10000)()
       n = ctypes.c_int(0)
       
       while self.state == CHIState.RUNNING:
           result = self._dll.chi_getdata(0, e_buffer, i_buffer, ctypes.byref(n))
           
           if result == 0 and n.value > len(self._data_points):
               # 有新数据
               for i in range(len(self._data_points), n.value):
                   point = ECDataPoint(
                       time=i * self._sample_interval,
                       potential=e_buffer[i],
                       current=i_buffer[i]
                   )
                   self._data_points.append(point)
                   
                   if self._data_callback:
                       self._data_callback(point)
           
           time.sleep(0.05)  # 50ms 轮询间隔
   ```

## 完整分析结果

### 1. 通信方式：DLL接口

**核心发现**: CHI电化学工作站采用 **`libec.dll`** 动态链接库进行通信

**通信本质**: 
- 不是串口通信（RS232/RS485）
- 不是网络通信（TCP/IP）
- 而是**本地API调用**（Windows DLL P/Invoke）

**技术实现**:
```csharp
[DllImport("libec.dll", CallingConvention = CallingConvention.Cdecl)]
```

---

### 2. 核心通信函数表

| DLL函数 | 功能 | 参数 | 返回值 |
|---------|------|------|--------|
| `CHI_hasTechnique(int x)` | 检查仪器是否支持某项技术 | x: 技术代码 | byte: 0=不支持, 1=支持 |
| `CHI_setTechnique(int x)` | 设置电化学技术类型 | x: 技术代码 | void |
| `CHI_setParameter(byte[] id, float value)` | 设置实验参数 | id: 参数ID字符串<br>value: 参数值 | void |

| `CHI_experimentIsRunning()` | 检查实验运行状态 | 无 | byte: 0=停止, 1=运行中 |
| `CHI_getExperimentData(float[] x, float[] y, int n)` | 获取实验数据 | x,y: 数据缓冲区<br>n: 数据点数 | void |
| `CHI_showErrorStatus()` | 显示错误状态 | 无 | void |
| `CHI_getErrorStatus(byte[] buffer, int length)` | 获取错误信息 | buffer: 错误信息缓冲区<br>length: 缓冲区长度 | void |
| `CHI_getParameter(byte[] id)` | 获取参数值 | id: 参数ID字符串 | float: 参数值 |

### 4. 典型通信流程

```csharp
// ====================
// 完整的CHI通信流程
// ====================

// 步骤1: 初始化连接
CHIInitialize(); 
// - 检测DLL是否可用
// - 查询支持的技术列表
// - 设置默认参数
// - 尝试运行CV以检测连接

// 步骤2: 检查技术支持
byte hasCV = CHI_hasTechnique(0); // 检查是否支持CV
if (hasCV == 1) {
    // 仪器支持CV技术
}

// 步骤3: 设置技术类型
CHI_setTechnique(0); // 0 = CV (循环伏安法)

// 步骤4: 设置实验参数
CHI_setParameter(Encoding.ASCII.GetBytes("m_ei"), 0.0f);   // 初始电位 0V
CHI_setParameter(Encoding.ASCII.GetBytes("m_eh"), 0.5f);   // 高电位 0.5V
CHI_setParameter(Encoding.ASCII.GetBytes("m_el"), -0.5f);  // 低电位 -0.5V
CHI_setParameter(Encoding.ASCII.GetBytes("m_ef"), 0.0f);   // 终止电位 0V
CHI_setParameter(Encoding.ASCII.GetBytes("m_vv"), 0.1f);   // 扫描速率 0.1V/s
CHI_setParameter(Encoding.ASCII.GetBytes("m_qt"), 5.0f);   // 静置时间 5s
CHI_setParameter(Encoding.ASCII.GetBytes("m_inpcl"), 2.0f); // 段数 2

// 步骤5: 启动实验
bool success = CHI_runExperiment();
if (!success) {
    CHI_showErrorStatus(); // 显示错误
    return;
}

// 步骤6: 数据采集循环（后台线程）
float[] x_data = new float[65536]; // X轴数据缓冲区
float[] y_data = new float[65536]; // Y轴数据缓冲区
int n = 65536;

while (CHI_experimentIsRunning() == 1) {
    // 获取实验数据
    CHI_getExperimentData(x_data, y_data, n);
    
    // 处理新数据点
    // ... 更新UI、保存数据等
    
    // 轮询间隔
    Thread.Sleep(50); // 50ms
}

// 步骤7: 实验完成
// - 自动保存CSV文件
// - 更新实验状态
// - 记录日志
```

### 6. 数据采集机制

**采集方式**: 主动轮询（Polling）

**关键参数**:
- **轮询间隔**: 50ms
- **缓冲区大小**: 65536个数据点
- **数据类型**: float数组
- **数据维度**: 二维 (X轴电位, Y轴电流)

**数据流程**:
```
实验运行 → 50ms轮询 → 检查状态 → 获取数据 → 
更新缓冲区 → 触发回调 → UI更新 → 继续轮询
```

**线程模型**:
```
主线程 (UI)
    ↓
启动实验
    ↓
后台工作线程 (BackgroundWorker)
    ├─ DoWork: 数据采集轮询
    ├─ ProgressChanged: 进度更新
    └─ RunWorkerCompleted: 实验完成处理
```

## 关键技术总结

### 协议本质
✅ **本地DLL接口** - 不是传统的串口或网络协议  
✅ **P/Invoke调用** - C#通过Platform Invoke调用C/C++ DLL  
✅ **同步+异步** - 参数设置同步，数据采集异步  

### 性能特点
- ⚡ **高性能**: 本地API调用，延迟极低
- 🔄 **实时性**: 50ms轮询间隔，准实时数据
- 💾 **大容量**: 65536点数据缓冲区

### 平台限制
- 🪟 **Windows专属**: 需要Windows环境
- 📦 **DLL依赖**: 必须安装CHI驱动和DLL
- 🔌 **硬件耦合**: 与CHI仪器紧密绑定

### 设计优点
- 📋 **参数化**: 字符串ID便于扩展
- 🧪 **可测试**: 内建模拟模式
- 🛡️ **容错**: 完善的错误处理
- 🔧 **灵活**: 支持多种电化学技术

## 技术决策记录

### 为什么使用DLL接口？
1. **性能要求**: 电化学实验需要实时数据采集
2. **厂商提供**: CHI Instruments提供了官方DLL
3. **Windows平台**: 目标平台为Windows桌面应用

### 为什么使用轮询而非事件？
1. **DLL限制**: libec.dll不提供事件回调机制
2. **简单可靠**: 轮询实现简单，不易出错
3. **性能可接受**: 50ms间隔对UI响应影响小

### 为什么需要模拟模式？
1. **开发便利**: 无需连接实际硬件即可开发
2. **测试支持**: 方便进行自动化测试
3. **演示功能**: 可用于产品演示
