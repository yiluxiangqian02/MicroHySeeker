### 2️⃣ 用户提问：冲洗配置同步问题

**用户提问**:
> 有一个问题 冲洗和系统控制中的冲洗配置是不是要同步和对应呢？

**我的分析**:

问题识别：
- **ConfigDialog（系统配置对话框）**：有冲洗通道配置表格，可以编辑泵地址、参数等
- **FlusherDialog（冲洗对话框）**：也有自己的配置界面（ComboBox、SpinBox）
- **存在问题**：
  - 两个对话框有重复的配置功能
  - 在一个地方修改配置，另一个地方不会自动同步
  - 可能导致配置不一致，用户混淆

**我的回复**:
> 是的！这确实是一个需要解决的问题。目前存在配置同步问题：
> 1. ConfigDialog 可以配置冲洗通道
> 2. FlusherDialog 也有配置界面
> 3. 两者没有同步机制
> 
> 建议方案：
> - ConfigDialog 作为唯一配置入口（Single Source of Truth）
> - FlusherDialog 改为只读显示，直接使用 SystemConfig 中的配置
> - 添加"刷新配置"按钮重新加载配置

## 技术实现总结

### 架构变更

**变更前**（双向数据流）:
```
ConfigDialog ←→ SystemConfig ←→ FlusherDialog
     ↓                              ↓
  编辑配置                       编辑配置
     ↓                              ↓
   保存配置                       应用配置
```
**问题**：两个编辑入口，容易产生不一致

**变更后**（单向数据流）:
```
ConfigDialog → SystemConfig → FlusherDialog
     ↓              ↓              ↓
  编辑配置        存储配置      只读显示
     ↓              ↓              ↓
   保存配置       写入配置      刷新显示
```
**优势**：单一数据源（Single Source of Truth），配置始终一致

## 设计理念

### Single Source of Truth（单一数据源）
- **ConfigDialog** = 唯一配置编辑入口
- **SystemConfig** = 权威数据存储
- **FlusherDialog** = 只读视图（消费者）

### Unidirectional Data Flow（单向数据流）
```
用户编辑 → ConfigDialog → SystemConfig → FlusherDialog 显示
                ↓              ↓              ↓
              验证规则        持久化         自动刷新
```

### Defensive Programming（防御式编程）
- 启动前检查配置完整性
- 缺失配置时禁用操作按钮
- 显示友好的警告信息
- 防止无效操作导致错误

### A. 配置解析逻辑
```python
def _parse_flush_channels(self):
    """解析系统配置中的冲洗通道（按工作类型分类）"""
    self._inlet_channel = None
    self._transfer_channel = None
    self._outlet_channel = None
    
    for ch in self.config.flush_channels:
        work_type = getattr(ch, 'work_type', '').lower()
        
        if work_type == 'inlet':
            self._inlet_channel = ch
        elif work_type == 'transfer':
            self._transfer_channel = ch
        elif work_type == 'outlet':
            self._outlet_channel = ch
    
    logger.info(f"冲洗通道解析完成: Inlet={self._inlet_channel is not None}, "
                f"Transfer={self._transfer_channel is not None}, "
                f"Outlet={self._outlet_channel is not None}")
```

### B. 配置完整性检查
```python
def _check_config_complete(self) -> bool:
    """检查冲洗配置是否完整（需要 3 个通道）"""
    complete = all([
        self._inlet_channel is not None,
        self._transfer_channel is not None,
        self._outlet_channel is not None
    ])
    
    if not complete:
        logger.warning("冲洗配置不完整，缺少必要通道")
    
    return complete
```

```python
def _update_display(self):
    """更新 UI 显示（只读标签）"""
    # 更新 Inlet 显示
    self.inlet_info_label.setText(
        self._get_channel_display(self._inlet_channel)
    )
    
    # 更新 Transfer 显示
    self.transfer_info_label.setText(
        self._get_channel_display(self._transfer_channel)
    )
    
    # 更新 Outlet 显示
    self.outlet_info_label.setText(
        self._get_channel_display(self._outlet_channel)
    )
    
    # 显示/隐藏警告横幅
    if not self._check_config_complete():
        self.warning_banner.show()
        self.warning_label.setText(
            "⚠️ 配置不完整：请在'系统设置'中配置所有冲洗通道"
        )
    else:
        self.warning_banner.hide()
```

### D. 刷新配置逻辑
```python
def _refresh_config(self):
    """重新从系统配置加载冲洗通道"""
    try:
        # 重新解析配置
        self._parse_flush_channels()
        
        # 更新 UI 显示
        self._update_display()
        
        # 检查配置完整性
        if self._check_config_complete():
            QMessageBox.information(
                self, 
                "刷新成功", 
                "冲洗配置已成功刷新"
            )
            logger.info("用户手动刷新冲洗配置成功")
        else:
            QMessageBox.warning(
                self, 
                "配置不完整", 
                "当前配置缺少必要的冲洗通道，请在系统设置中完善配置"
            )
            logger.warning("刷新后配置仍不完整")
            
    except Exception as e:
        logger.error(f"刷新配置失败: {e}")
        QMessageBox.critical(
            self, 
            "刷新失败", 
            f"刷新配置时发生错误: {str(e)}"
        )
```
