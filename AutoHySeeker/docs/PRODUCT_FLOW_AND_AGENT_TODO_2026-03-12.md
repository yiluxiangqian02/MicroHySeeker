# AutoHySeeker Web 产品主线校准（2026-03-12）

> 目的：把当前 Web 前端从“电化学参数向导 + Agent 卡片展示”校正为真正对齐 MicroHySeeker 单次实验编辑器与 5 Agent 响应事件流的产品骨架。

---

## 一、当前核心偏差

1. **创建实验页做成了 technique 向导，不是真实实验步骤编辑器**
   - 当前前端主要围绕 CV/EIS/CA/CP/LSV/DPV/SWV 选择和参数输入
   - 但 MicroHySeeker 的实验对象是 `Experiment.steps[]`
   - 每个 step 具有明确 `step_type` 与特定字段，而不是单一“电化学方法表单”

2. **Agent 的名字和职责定义仍偏 UI 包装，不够贴近真实工作流**
   - “数据解读助手”应升级为“数据处理/分析助手”
   - “知识检索助手”应升级为“知识库 Chat 入口”
   - “运行监护助手”缺少明确监控输入、判定规则和联动流程

3. **运行中的实验语义不清楚**
   - 页面显示“运行中”，但没有讲清实验名称、来源、当前 step、为何被判定为 running

## 二、MicroHySeeker 单次实验编辑器：真实 step type 映射

来源：`MicroHySeeker/src/models.py`

### 2.1 真实 6 类 step type

| step_type | 目的 | 核心字段 | Web 端应如何呈现 |
|---|---|---|---|
| `prep_sol` | 配液/混液 | `prep_sol_params` | 配液步骤编辑器：选溶液、目标浓度、是否溶剂、注液顺序、总体积 |
| `transfer` | 移液/转移 | `pump_address`, `pump_direction`, `pump_rpm`, `volume_ul` / `transfer_duration`, `transfer_duration_unit` | 移液步骤编辑器：选泵、方向、速度、按体积或按时长执行 |
| `flush` | 冲洗 | `flush_channel_id`, `flush_rpm`, `flush_cycle_duration_s`, `flush_cycles` | 冲洗步骤编辑器：选冲洗通道、转速、每轮时长、循环次数 |
| `echem` | 电化学测试 | `ec_settings` | 电化学步骤编辑器：Technique + 对应参数 |
| `blank` | 空白/占位/等待 | `notes`（可扩展 duration） | 空白步骤编辑器：用于留空、占位、手动观察、备注 |
| `evacuate` | 排空 | 复用泵/通道逻辑（当前模型只通过 `step_type` 区分） | 排空步骤编辑器：明确排空目标、通道、持续时间/体积 |

### 2.2 每类步骤的 UI 要求

#### A. `prep_sol`
- 不该缩减成“目标方法 + 电化学参数”
- 应至少支持：
  - 可选溶液列表
  - 每种溶液目标浓度
  - 是否溶剂
  - 注液顺序 / 同批次注液编号
  - 总体积 `total_volume_ul`
- 输出应直接映射 `prep_sol_params`

#### B. `transfer`
- 要支持两种执行模式：
  - 按体积 `volume_ul`
  - 按时间 `transfer_duration + transfer_duration_unit`
- 需要显式显示：泵地址、方向、转速

#### C. `flush`
- 必须以 **flush channel** 为中心，而不是普通泵参数拼接
- 必须支持循环次数

#### D. `echem`
- `echem` 才是 technique 的承载步骤
- 其中 `ec_settings.technique` 才区分：CV / LSV / i-t / EIS / ADT
- 所以前端应是：
  - 先选 step type = `echem`
  - 再选 technique
  - 再根据 technique 展示参数

#### E. `blank`
- 用于等待、占位、人工观察、流程分段
- 当前 Web 尚未承接

#### F. `evacuate`
- 排空不是 flush/transfer 的文案替身，应独立呈现为明确动作
- 当前 Web 尚未承接

## 三、创建实验页重构原则

### 当前错误模式
- 研究目标 → technique → technique 参数 → 创建实验

### 目标模式
- 实验信息 → 步骤列表 → 为每个步骤选择 `step_type` → 编辑该 step 的真实参数 → 预览完整 Experiment JSON

### 目标结构
1. **实验级信息**
   - 名称
   - 描述
   - tags
   - operator（可后续补）

2. **步骤编排区**
   - 添加步骤
   - 排序
   - 复制
   - 删除
   - 每步显示 step summary

3. **步骤参数编辑区**
   - 根据 `step_type` 动态切换表单

4. **执行前预览**
   - 预览完整步骤链
   - 显示总预计时长 / 风险点 / 需要确认项

| 现名称 | 调整后建议 | 核心职责 |
|---|---|---|

## 五、5 个 Agent 响应事件流（第一版）

### 5.1 方案设计助手
- **输入事件**
  - 用户新建实验
  - 用户要求补齐参数
  - 用户要求下一轮实验建议
- **读取上下文**
  - 当前实验目标
  - 历史相似实验
  - 可用方法模板
- **输出结果**
  - 推荐 step 组合
  - 参数建议
  - 风险提示
- **写回位置**
  - 创建实验页建议区
  - 实验详情页“下一步建议”区

### 5.2 知识管理 / 知识库 Chat
- **输入事件**
  - 用户在聊天框提问
  - 用户从实验详情页发起“问知识库”
- **读取上下文**
  - 实验上下文
  - 历史实验
  - 文档 / 知识库
- **输出结果**
  - 对话回答
  - 引用来源
  - 可复用方案/经验
- **写回位置**
  - 聊天消息流
  - 可选保存到实验备注/知识卡片

### 5.3 数据处理/分析助手
- **输入事件**
  - 实验完成
  - 用户指定一个或多个 run 做分析
  - 用户要求绘制目标期刊风格图
- **读取上下文**
  - echem CSV
  - run_summary / run_log
  - 目标绘图要求
- **输出结果**
  - 关键指标
  - 结构化分析结果
  - 图表 / 对比图 / 报告摘要
- **写回位置**
  - 实验详情页结果区
  - 结构化 analysis record
  - 导出文件区

### 5.4 运行监护助手
- **输入事件**
  - 实验开始执行
  - 运行状态轮询
  - 新日志 / 新采样数据 / 超时 / 状态异常
- **监控对象**
  - 实验状态机
  - 当前 step
  - 泵动作是否超时
  - 电化学采样是否中断
  - 是否出现 warning / error / 长时间无进展
- **输出结果**
  - 运行中摘要
  - 风险/异常标签
  - 是否升级为故障排查
- **写回位置**
  - 首页运行卡片
  - 实验详情页运行时间线
  - 异常事件流

### 5.5 故障排查助手
- **输入事件**
  - 运行监护助手判定异常
  - 用户手动点击“排查”
  - 实验失败结束
- **读取上下文**
  - 运行日志
  - 最近步骤
  - 设备状态
  - 错误码 / 超时记录 / 数据异常模式
- **输出结果**
  - 故障分类
  - 可能原因排序
  - 建议排查路径
  - 是否可恢复 / 是否需要停止
- **写回位置**
  - 故障面板
  - 实验详情页故障报告

## 六、关键联动：运行监护助手 → 故障排查助手

### 触发条件（第一版）
1. 连续多次状态轮询无进展
2. step 执行超出预计时长阈值
3. 日志出现 error/timeout/communication failure
4. 电化学采样中断或显著异常
5. 泵执行记录缺失/返回异常

### 联动流程
1. 运行监护助手标记异常事件
2. 生成异常上下文包（实验ID、step、最近日志、最近状态、最近数据）
3. 自动触发故障排查助手
4. 故障排查助手返回：
   - 故障类型
   - 可能原因
   - 建议动作
5. 前端展示：
   - 当前实验卡片变为风险态
   - 详情页时间线增加异常节点
   - 提供“继续观察 / 暂停 / 停止 / 人工确认”入口
